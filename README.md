# 🎃 南瓜留船（poi-plugin-nangua-liuchuan）

一个 [poi](https://github.com/poooi/poi)（舰娘浏览器）插件：查询你已有舰娘的信息，根据「运」值计算**额外捞船**数量，支持**收藏置顶**和**在新窗口打开**。

## 功能

- **查询已有舰娘**：读取 poi 数据存储（`info.ships` + `const.$ships` + `const.$shipTypes`），与「舰娘信息」插件使用同一数据源，无需额外安装其它插件。
- **计算额外捞船**：对每一艘「运」值低于目标值（默认 51）的舰娘计算额外捞船数。
- **表格列**：舰种、舰娘、Lv、火力、雷装、火力+雷装、当前运、剩余运、已捞、剩余捞船、まるゆ(估)。
- **留船等级上限**：设置区可填写等级上限（默认 0 = 不筛选）。低于上限的舰全部从列表筛除（不视为主力舰），等级 ≥ 上限的船为主力舰。
- **已捞（每行）**：该舰所在**舰线**（同一改造链，如 長波/長波改/長波改二）中「上锁（`api_locked`）且等级不足（Lv < 留船等级上限）」的舰数，不是总数，每行对应本舰线。
- **剩余捞船**：每行 = ⌈剩余运/3⌉×2 − 已捞（本舰线）；基数 ⌈剩余运/3⌉×2 本身为偶数，相减后不再取偶；**为 0 时显示 ✅**。
- **点击表头排序**：任意列点击表头即可排序，再次点击切换升/降序（▲/▼ 指示）；收藏的舰娘始终置顶。
- **舰种筛选**：列表上方可选择舰种，只显示该舰种的舰娘（选「全部舰种」恢复）。
- **收藏置顶**：点击舰娘行首的 ☆/★ 收藏/取消收藏；收藏的舰娘固定排在列表最前（📌 标记），收藏列表保存在 poi 配置中，**重启 poi 不丢失**。
- **在新窗口打开**：poi 的插件设置（点插件行右侧 ⚙ 齿轮）里有内置的 **Open plugin in new window** 开关，勾选后本插件会在独立窗口打开（默认跟随插件导出值 `windowMode`）。
- **可调参数**：目标运值（默认 **51**）、公式除数（默认 3）、乘数（默认 2）都可在插件顶部设置区修改，点击「恢复默认」一键还原。
- **自动刷新**：母港数据更新（出击归来、改造、喂运等）后自动重新计算。

## 公式说明

每行剩余捞船：

```
剩余捞船 = ⌈剩余运 ÷ 除数⌉ × 乘数 − 已捞（本船）
```

其中：

```
剩余运 = 目标运 − 当前运
已捞（本船）= 该舰所在舰线（同一改造链）中「上锁且 Lv < 留船等级上限」的舰数
```

默认值代入（目标运 51、除数 3、乘数 2）：

```
剩余捞船 = ⌈(51 − 当前运) ÷ 3⌉ × 2 − 已捞（本船）
```

**基数 ⌈剩余运 ÷ 除数⌉ × 乘数 本身为偶数**（乘数 2），相减后的结果不再取偶，小于 0 按 0 计。

示例（Mogador改，⌈剩余运/3⌉×2 = 8）：

| 留船等级上限 | 已捞（本舰线） | 剩余捞船 |
| ------------ | -------------- | -------- |
| 30           | 0              | 8 − 0 = 8 |
| 60           | 4              | 8 − 4 = 4 |

> 已捞按**舰线**统计：同一艘舰的各个改造形态（如 長波/長波改/長波改二）归为同一舰线，
> 长波改二 一行显示的是这条舰线里上锁且等级不足的总舰数（例如 12）。

> 剩余捞船为 0 的舰娘行显示 ✅。
> 每行剩余捞船 = ⌈剩余运/3⌉×2 − 已捞（本舰线），小于 0 按 0 计。

| 当前运 | 剩余运 | 剩余捞船 |
| ------ | ------ | -------- |
| 50     | 1      | 2        |
| 48     | 3      | 2        |
| 45     | 6      | 4        |
| 41     | 10     | 8        |
| 20     | 31     | 22       |

> 上表为「已捞 = 0」时的参考值；实际每行剩余捞船 = ⌈剩余运/3⌉×2 − 已捞（本舰线）。
> 表格里的「まるゆ(估)」为把运提升到目标值所需的まるゆ数量估算（每只平均 +1.6 运，向上取整），仅供参考。

## 安装（重要：目录结构）

poi 扫描的是 **`plugins/node_modules/` 下的 `poi-plugin-*` 文件夹**（见 poi 源码 `views/services/plugin-manager` 与 `views/env`），所以插件必须放在 `node_modules` 里，直接丢进 `plugins/` 根目录是**不会**被识别的。

正确做法（Windows）：

```
%APPDATA%\poi\plugins\node_modules\poi-plugin-nangua-liuchuan\
  ├── package.json
  ├── index.es
  └── README.md
```

1. 打开资源管理器，地址栏输入 `%APPDATA%\poi\plugins` 回车（如果没有 `node_modules` 文件夹就新建一个）。
2. 把 `poi-plugin-nangua-liuchuan` 整个文件夹放进 `plugins\node_modules\` 里。
3. 完全关闭并重新打开 poi，在左侧「插件」抽屉里找到「南瓜留船」并启用（如果之前安装过失败版本，先点一下插件的「Reload」）。
4. 进入游戏母港等待数据同步即可。

> 若你的 poi 是绿色版/便携版，插件目录可能在 poi 程序目录下的 `plugins\node_modules\`，以 poi 实际读取的路径为准（可在 poi 的插件设置页看到已安装插件的路径提示）。

## 插件名显示

poi 插件列表显示的标题来自 package.json 的 `poiPlugin.title` 字段（驼峰 `poiPlugin`，不是 `poi-plugin`），本插件已设为 **南瓜留船**。注意：包名 `name` 必须以 `poi-plugin-` 开头，否则 poi 会拒绝加载（`Plugin package name is invalid`），所以包名保持英文、显示名用 `poiPlugin.title`。

## 数据来源

- `store.getState().info.ships` —— 玩家已有舰娘（含当前运 `api_lucky[0]`、火力 `api_karyoku[0]`、雷装 `api_raisou[0]`）
- `store.getState().const.$ships` —— 舰娘图鉴（名称、舰种编号）
- `store.getState().const.$shipTypes`（旧版 poi 为 `$stypes`）—— 舰种名称

另外，插件会监听 `plugin.message` 事件：如果「舰娘信息」等其它插件以
`{ type: 'ship-info.ships', body: [{ id, name, luck, ... }] }`（或 `nangua-liuchuan.ships`）广播舰娘数据，本插件也会直接采用，作为 store 数据的补充来源。

## 兼容性

- **poi v10+**：插件入口具名导出 `reactClass`（主界面组件）与 `windowMode`（新窗口开关默认值），本插件均已导出；数据通过 `import('views/create-store')` 动态获取，设置与收藏通过 poi 配置（`remote.require('./lib/config')`，路径 `poi.plugin.nangua-liuchuan.*`）持久化。
- **旧版 poi（v9 及更早）**：通过 `default` 导出与 `props.store / props.config / props.setConfig` 兼容。
- 都不行时退回 `localStorage` 保存设置与收藏。
